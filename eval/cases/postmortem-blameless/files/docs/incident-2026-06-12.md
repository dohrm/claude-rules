# Raw notes — checkout outage, 12 June 2026

Collected from the alert channel and the deploy log. Not cleaned up.

- 09:12 — Sam merged PR #412 (add a `currency` column to `order_line`, with a
  backfill in the same migration).
- 09:20 — the release pipeline promoted build 2291 to production.
- 09:21 — the migration started. It took an `ACCESS EXCLUSIVE` lock on `order_line`
  (18 M rows) to add the column with a default.
- 09:23 — checkout latency climbed; requests began timing out at the gateway.
- 09:26 — the "checkout availability — slow burn" ticket alert fired. Nobody was
  watching the ticket queue.
- 09:41 — a customer email reached support, who asked in the platform channel.
- 09:44 — Priya saw the message and started looking.
- 09:52 — Priya found the lock in `pg_stat_activity` and cancelled the migration.
- 09:53 — latency recovered. Orders resumed.
- 10:30 — the migration was re-run as an add-column-nullable, then a separate
  batched backfill. No further impact.

Other facts:
- There is no fast-burn page configured for checkout, only the slow-burn ticket.
- The staging database holds 40 000 rows, so the migration took 200 ms there.
- The runbook for checkout has no entry about migrations.
- Error budget for the month: 43 minutes. This incident consumed 31 of them.
