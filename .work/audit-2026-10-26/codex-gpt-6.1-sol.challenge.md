## Verdicts

- **`autonomy.kit.disputed-critical-has-no-exit-but-reroll` — change.** Keep the verification-and-escalation clause. Drop the optional same-tree verdict lock until its recovery path is specified: an unsupported CRITICAL can legitimately require human adjudication without changing code. The proposed lock would preserve precisely that false positive indefinitely. `rules/agent/autonomy.md:53,188-192` establishes reviewer authority and escalation; `kit/common/review-guard.mjs:231-237` supplies no adjudication mechanism. Also narrow “re-reviewing an unchanged tree is banned” to verdict shopping; correcting an incomplete review is already required by `review-guard.mjs:172-178`.

- **`autonomy.skills.loop-done-command-not-frozen-nor-failing-first` — change.** Validate the command before launch, but treat an already-satisfied objective as immediate completion. Mandatory red is an explicit **L4** restriction, including exclusion of conditions that cannot fail first (`rules/agent/autonomy.md:106-109`), rather than a universal prerequisite. Freezing every file executed by the command also obstructs legitimate test-maintenance chores: loop-setup explicitly supports “all tests green” (`skills/loop-setup/SKILL.md:35`). Preserve acceptance semantics; escalate changes that weaken them. Existing doctrine already prohibits weakening assertions (`autonomy.md:188-192`).

- **`autonomy.kit.fresh-green-handback-is-prose-only` — change.** Retain as an optional experiment, below demonstrated contract defects. The synthesis overstates existing enforcement: pre-push consumes the review report, not evidence of a fresh `just check` (`rules/agent/autonomy.md:42-43`). Specify how consuming repositories wire their manually adapted `check` recipe, what the hash includes, and when it is captured. A tracked-only comparison misses newly created files; hashing committed state files can invalidate the marker during ordinary progress logging (`skills/loop-setup/SKILL.md:60-61,96-100`). A fail-open, once-blocking hook is assistance, not proof.

- **`autonomy.skills.trigger-routing-not-mechanized` — change.** Cut the mandatory TF-IDF ranking and similarity gates. No evidence establishes that lexical similarity predicts either supported host’s skill selection; `test/skills.test.mjs:1-4` explicitly distinguishes static lint from behavioral evaluation. Otherwise we would optimize descriptions for our substitute router. Keep a small human-authored routing scenario set and evaluate actual selection through the manual harness. Recurring semantic judgment does not become deterministic merely because its proxy is.

- **`autonomy.eval.prompt-independent-compliance` — keep.** Neutral and competing prompts add a useful behavioral dimension while preserving existing artifact and gate assertions (`eval/README.md:24-34`). Keep the initial set small, consistent with the few-high-value-cases constraint at `eval/README.md:48-52`.

- **`autonomy.skills.measured-optimization-branch` — change.** Keep only as a conditional, on-demand reference for an explicitly requested optimization chore. Loop-setup supports repeated chores and excludes feature work (`skills/loop-setup/SKILL.md:23,60-63`); “faster” alone does not establish that the task belongs there. Fixed workloads and correctness checks are useful, but the synthesis cites no local failure warranting a mandatory branch.

- **`maintenance.docs.claude-native-agents-fallback` — keep.** The correction is supported by the [official memory documentation](https://code.claude.com/docs/en/memory#agents-md). Retain existing emission architecture. Clarify that fallback co-loading with `.claude/rules/` is documented behavior; whether generated Codex pointers cause duplicate reads remains an untested consequence. `docs/agent-sharing.md:81` restricts the installer’s cross-import policy, so vendor fallback alone does not establish an installer violation.

- **`maintenance.skills.transcript-backed-session-diagnosis` — change.** Keep the idea conditional on an explicit request to investigate an earlier session. Extending `/debrief` requires updating its discovery contract: its description currently limits it to implementation “just finished in this conversation” (`skills/debrief/SKILL.md:3`). Identify supported transcript formats before confirming M; otherwise “documented transcript adapters” is an unbounded maintenance promise.

- **`cost.eval.no-control-arm-so-cases-cannot-show-the-asset-earns-its-tokens` — change.** Keep repeated runs and paired controls, but specify a valid control prompt. Default agent prompts explicitly require the installed subagent (`eval/run.mjs:68-69`), and the harness fails when it was not invoked (`eval/run.mjs:372-374`). Removing that agent while retaining those requirements guarantees control failure independently of task quality. Use a neutral task prompt and behavioral assertions in both arms; record invocation separately. A control pass establishes redundancy for that scenario, not that the whole asset earns nothing.
